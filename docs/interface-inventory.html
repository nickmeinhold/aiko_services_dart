Aiko Services · Dart port · reference

The interface inventory — the port skeleton

Every Interface in Aiko's object model, its abstract-method contract, its inheritance edges, and its target Dart shape. The skeleton the port pours into, and the cross-check for Andy's interface designs. Built on the validated composition mapping.

◆ The mapping principle

One Python Interface + its Impl = one Dart mixin. Abstract methods become abstract mixin members; the impl body becomes the concrete method; the class X(A, B) parents become on constraints; the impl's __init__ becomes a per-slice _initX(ctx). But not every collaborator is an Interface — ECProducer/ECConsumer are plain classes held as fields (delegation, HAS-A), not slices (mixin, IS-A). The inventory records the kind of each node.

1 · The inheritance graph — where the diamonds are

Every composed type traces back to Service, which is itself ServiceProtocolInterface + Hooks. The deep node is HyperSpace(Category, Actor) — it reaches Actor (and therefore Service, Hooks) through two paths. That is the ultimate exercise of the call_init idempotency guard.

ServiceProtocolInterface  (marker)      Hooks  (standalone)
                    \                    /
                     Service ─────────────
                        │
                      Actor ───────────────┐
                     /   │   \             │
       ProcessManager  Storage  PipelineElement   Dependency (standalone)
                                    │        \      /
                                 Pipeline    Category ── (Actor + Dependency)
                                                 │
                                            HyperSpace ── (Category + Actor)  ← deepest diamond
                                                          Actor reached twice → inits once

2 · Foundation slices

Hookson CallInitmixin
Interface.default("Hooks", "…hook.HooksImpl") · standalone; Service depends on it. Extensible pre/post hook registry.
  • add_hook(name) · remove_hook(name) · get_hook(name) · get_hooks()
  • add_hook_handler(name, fn, options=None) · remove_hook_handler(name, fn)
  • run_hook(name) · set_hook_enabled(name, flag)
ServiceProtocolInterfaceextends Interfacemarker
Empty marker. Signals "this is an Aiko Service implementing a protocol." In Dart: a marker interface (empty abstract interface class) or simply omitted — no methods to carry.
Service(ServiceProtocolInterface, Hooks)mixin
Interface.default("Service", "…service.ServiceImpl") · the root behaviour. Init slice: name, protocol, tags, transport, service_id, topic_path + topic_{in,out,control,log,state}; registers with the process. Absence-safe: service_id/topic_path start null.
  • run() · stop()
  • add_message_handler(handler, topic, binary=False) · remove_message_handler(handler, topic)
  • set_registrar_handler(fn) · registrar_handler_call(action, registrar)
  • add_tags(tags) · add_tags_string(str) · get_tags_string()
Actor(Service)mixin
Interface.default("Actor", "…actor.ActorImpl") · ActorImpl.__init__ first line is call_init("Service"). Adds the message-mailbox model, self.share (lifecycle/log_level/running) + an ECProducer collaborator, delayed-message queue. This is the unit of the isolate-per-actor runtime.
  • run(mqtt_connection_required=True) · set_log_level(level)
Dependencyextends Interfacemixin
Interface.default("Dependency", "…dependency.DependencyImpl") · standalone (NOT a Service). Init sets four fields; service = None is a normal, first-class state (not discovered / absent). This nullability is load-bearing across the object model.
  • get_type() · is_type(type_name)
  • update(entry_name, service=None, service_filter=None, lifecycle_manager_url=None, storage_url=None)

3 · Object model

Category(Actor, Dependency)composed
The acid test — two disjoint branches (Actor→Service→Hooks, and Dependency) flattened onto one object. A Category is a group of Entries, each itself a Category or a Dependency. Init: call_init("Actor") then call_init("Dependency", service_filter=…); adds an entries share.
  • add(entry_name, service_filter=None, lifecycle_manager_url=None, storage_url=None)
  • list(topic_path_response, entry_name=None, long_format=False, recursive=False, entry_records=None)
  • remove(entry_name) · exit()
HyperSpace(Category, Actor)composed
The deepest node — a Category that is also directly an Actor, so Actor/Service/Hooks are reached twice. Init calls call_init("Actor") then call_init("Category"); the guard makes the shared slices init once. The typed CRUD API over the whole space (kept deliberately separate from the EC observation channel).
  • create(category_path) · destroy(category_path) · dump()
Registrar(Service)composed
Zero abstract methods. A Service whose entire contract is the wire protocol — message handlers (_topic_in_handler, _service_add, _service_remove) + a primary/secondary state machine for leader election. In Dart: a Service-composed class, no new mixin surface. Its "interface" lives on the bus, not in the type.
Storage(Actor)mixin
Interface.default("Storage", …) · persistence for Categories/Dependencies. Entry = either a Category or a Dependency (the same duality as HyperSpace).
  • initialize(storage_url) · create(category_name) · destroy(entry_name) · exit()
  • add(dependency_name, dependency=None) · remove(entry_name) · link(new, existing)
  • update(entry_name, service=None, …) · list(topic_path_response, entry_name=None, …) · dump(sort_by_name)

4 · Lifecycle — the public/private interface split

Lifecycle introduces a pattern worth naming: each role splits into a public interface and a private interface, composed together in one impl (LifeCycleManagerImpl(LifeCycleManager, LifeCycleManagerPrivate)). Public methods are the API; _-prefixed private methods are internal machinery kept off the public contract. In Dart this maps to two mixins on one class — or a public mixin + a library-private mixin.

LifeCycleManagerextends ServiceProtocolInterfacemixin
  • lcm_create_client(parameters=None) · lcm_delete_client(client_id)
LifeCycleManagerPrivateextends Interfacemixin (private)
  • _lcm_create_client(…) · _lcm_delete_client(client_id, force=False)
  • _lcm_get_clients() → Dict · _lcm_get_handshaking_clients() → List
  • _lcm_lookup_client_state(client_id, key)
LifeCycleClient / LifeCycleClientPrivateServiceProtocolInterface / Interfacemixin pair
  • (private) _lcc_get_lifecycle_manager_topic() · _lcc_lifecycle_manager_change_handler(service_details)
Public LifeCycleClient's surface is largely the handshake protocol + Service; the private mixin carries the manager-tracking internals.

5 · Execution

ProcessManager(Actor)mixin
Spawns/supervises OS processes for actors. The isolate-spawn analog in the Dart runtime.
  • create(command, arguments=None, uid=None) · destroy(uid, kill=False) · exit(grace_time) · list(topic_path_response, uid=None) · dump()
PipelineElement(Actor)mixin
The unit of stream processing. process_frame returns (StreamEvent, dict) — the frame-transform contract.
  • process_frame(stream, **kwargs) → (StreamEvent, dict)
  • start_stream(stream, stream_id) · stop_stream(stream, stream_id)
  • create_frame(…) · create_frames(…) · get_stream() · get_variables() · get_parameter(name, …) · my_id(all=False)
Pipeline(PipelineElement)mixin
A PipelineElement that orchestrates a graph of PipelineElements (also PipelineElementLoop, PipelineRemote variants). Parses a pipeline definition, manages streams.
  • create_stream(stream_id, graph_path=None, …) · destroy_stream(stream_id, graceful=False)
  • set_parameter(stream_id, name, value) · set_parameters(stream_id, parameters)
  • process_frame_response(…) · parse_pipeline_definition(pathname) [classmethod]

6 · Collaborators — NOT mixins

These are plain classes an Actor holds, not slices it is. They map to ordinary Dart classes held as fields. Getting this boundary right is what stops the port from over-mixining.

ECProducerplain class · self.ec_producer = ECProducer(self, self.share)collaborator
The observation channel's write side. Wraps an Actor's share dict and publishes deltas. Distinct on purpose from the typed CRUD API (HyperSpace/Category). Eventual-consistency: subscribe → snapshot → deltas.
  • get(item_name) · update(item_name, value) · remove(item_name) · add_handler(fn) · remove_handler(fn)
ECConsumerplain classcollaborator
The observation channel's read side — subscribes to a producer's share, receives snapshot + deltas, exposes cached state.
  • add_handler(fn) · remove_handler(fn) · terminate() · (cache) get_services() · get_state() · get_history() · wait_ready()

7 · The Dart translation rules

PythonDart
class X(Interface) pure-abstractmixin X on CallInit
class X(A, B) (A, B interfaces)mixin X on CallInit, A, B
the Impl.__init__ bodyvoid _initX(Context ctx) => callInit(ctx, 'X', () {…})
call_init(self, "A", ctx) first line_initA(ctx); at top of _initX
the concrete composed classclass X with CallInit, …slices { X(ctx){ _initTop(ctx); } }
public + _private interface pairpublic mixin + library-private mixin on one class
marker interface (empty)omit, or empty abstract interface class
self.ec_producer = ECProducer(…)plain field: final ECProducer ecProducer;
service = None (absent)Object? service; — null is normal

Open edges (unchanged from the mapping note): isolate boundaries (composed objects don't cross by reference), F-bounded generics (none sampled needed them), and the message/transport layer (Message, MQTT) which is a separate abstraction, not part of the Interface composition system.
