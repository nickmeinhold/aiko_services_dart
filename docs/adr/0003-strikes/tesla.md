**Summary:** Tesla: "If you want the secrets of the universe, think in energy, frequency and vibration." Four Reply cases hum where the wire only has two, and the free-string reply topic is the frequency that arcs this type to ground on an unauthenticated bus.

**Fatal flaws:**
- **Correction 1 is the fourth misreading: English "when" was compiled into `CorrelationToken?`.** s_02 §2 puts the token *inside the reply method's payload* — `(found <token> <results…>)` — and the catalog signatures (`find(filters, reply_topic)`, `grant(duration, reply_topic)`, live Registrar `share(topic_response, …)`, `history(topic_response, count)`) carry **no token argument at all**. A nullable envelope field is not "conformance"; it is an optional positional on an S-expression, where omitting `<token>` and sending `(found <results…>)` cannot be distinguished from a token that *is* the first result. Two implementations will pick opposite grammars (the ADR already admits this in Open Question 1) and then call the mismatch a peer bug. Multiplexing was a parenthetical; the type made it a wire fork.
- **`Deferred` is a promise wearing a sealed class.** P1 forbids "wrapping message sends in futures/promises as a core API." The ADR's defence is syntactic: nothing `await`s. The frequency does not care. `Deferred` is the handler returning "I will send." That is the obligation the Consequences section names and then *declines to compensate*, while P1's 2026-07-07 amendment says at-most-once is legitimate **only if stated and compensated at the endpoints**, and forbids code that assumes a send happened. A correlation with no reply is lost, in-flight, or never-promised: three states, one silence. At 03:00 the requester waits on a case the type cannot discharge. s_02's own sketch is the recast: `find` **returns nothing**; "later" is an ordinary publish, which is already `NoReply`.
- **Correction 3 over-steers: it dumped every N-publish onto `topic_out`.** Pattern 3 is unsolicited sequences on the service's `topic_out` or Pipeline edges (frames, detections, telemetry). Pattern 2's own example is already plural — `<results…>` — and the live Registrar verbs `share` / `history` reply *N times or N items to a caller-supplied `topic_response`*, not to `topic_out`. Teaching handler authors that multi-result genuine requests are pattern 3 will publish where no caller is subscribed. Reply-N-times is not a fourth `Reply` case either: it is pattern 2, handler-mediated, which this type can only express as `NoReply` plus publishes. The table's "nothing here — it is pattern 3" is the lie that will ship.
- **`ReplyError` does not enforce "no exceptions cross the wire"; it forges a second path and then cannot walk the first.** s_02 §2: a failed request produces an error *message to the reply topic* **or** an error value in shared state, **per the owning interface's spec** — not a framework diagnostic string. The current `MessageDispatcher.dispatch` still must `catch`, and it still does not know which argument is the reply topic (`share`/`history` put it first; `find`/`grant` put it last; unknown commands have no handler to ask). `ReplyError` *requires* a destination the generic dispatcher cannot populate, so the catch site the case was invented to retire remains, now beside a typed case that claims to have replaced it. A `String diagnostic` also freezes a payload grammar s_02 explicitly deferred.
- **The under-counted blast radius: `final String topic` on an unauthenticated MQTT bus is a confused-deputy primitive.** s_02 §2: the response is a one-way message to **an interface method the caller implements**; §4: a request **MUST name its reply interface**. The ADR models an unconstrained MQTT address the dispatcher will publish to. A hostile or buggy peer names another actor's `in`, a `control` topic, spoofed telemetry on `out`, or a retained well-known path; a handler copies `args[n]` into `ReplyTo`/`ReplyError`/`Deferred`; the framework publishes. `ReplyError`'s diagnostic (`$command: $exception` in today's dispatcher) then leaks internals onto an attacker-chosen topic. `Deferred` delays the same publish until it is uncorrelated. The type has no refuse-destination, no caller-owned allow, no room not to send. They surfaced the unknown-command three-way split and left this one humming.
- **Source rank was inflated, then the dispatcher was asked to be the protocol.** s_02's header is `draft-for-verification`; P1 is `normative`. The ADR calls both normative and then privileges the draft's parenthetical token over the running Python (`do_request` has no correlation id; `actor.py` logs unknown commands and publishes nothing). At the dispatcher seam the information is two-valued: publish now, or do not. Four cases are the overtone of three patterns. `NoReply` already covers pattern 1, pattern 3, later handler sends, and shared-state errors. The extra two cases (`Deferred`, `ReplyError`) are the crystal faults.

**What holds:**
- Correction 2 is true: there is no implicit reply channel; `ReplyNow` was the discipline eating itself and it is right that it died.
- `String?` is genuinely inexpressible: it cannot carry a destination, and that is a representation problem, not a tuning problem.
- A sealed *datum* describing an immediate send is not a `Future`, and `ReplyTo` as data does not itself violate P1's ban on promises in the core API.
- Recording the less-preferred-pattern risk, refusing to tie-break Andy's unknown-command split, and holding `lib/` until the type is struck are the right kinds of caution.
- The `actor.py` unknown-command reading matches the supplied source: diagnostic, log, no publish.

**If RECAST, what to fold back:**
- Collapse the handler return to two cases: `NoReply` | `Send(destination, payload)`. Token lives in the payload per the reply interface (`found`), never as a nullable sibling of topic. If multiplexing is in scope, the token is **always present** on the wire — never an optional positional.
- Delete `Deferred`. Later sends are ordinary outbound messages from the actor, the same as Python; returning `NoReply` is the type of "not through this return value." Endpoint compensation for at-most-once (timeout / observe-state) lives at the requester, and this ADR must name that rather than leave an unenforceable IOU.
- Delete `ReplyError`. Success and failure are payload shapes of `Send`, per the owning interface. The dispatcher `catch` remains a catch. Unknown commands without a known destination stay `NoReply` plus a log, which is what `actor.py` already does.
- Replace `String topic` with a destination the bus may refuse: caller-declared reply topic after a same-namespace / caller-owned / default-deny check. A hostile reply topic must not become a publish. s_02's "reply interface" is the protocol; MQTT topic is only the binding, and it is not trusted input.
