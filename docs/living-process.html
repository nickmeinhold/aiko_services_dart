Aiko concepts

Aiko Services is a framework for building systems out of small message-passing actors. Tap ▶ show me to watch a concept happen.

Foundations
Actor
An independent unit that owns some private state and only ever talks by sending messages. The whole system is a graph of actors.
Message & Topic
Actors address each other by a topic name on a shared bus — never by memory. The topic is the only address, so location is invisible.
Transport (MQTT)
The bus itself. Aiko uses MQTT today, but the transport is pluggable. The amber center of the diagram is the broker.
Service & Protocol
Every actor advertises a protocol:version so others know how to speak to it (e.g. category:0).
Structure
Category
A live actor that groups entries — other categories, or references to services. Think of it as a folder that is itself alive.
HyperSpace
The root: a tree of categories with path names like channels/general. It also manages their lifecycle.
Dependency
A reference to a service that may not exist yet — service = null — until it is discovered and resolved.
Storage
HyperSpace can be persisted (file, sqlite, mqtt) so the tree of actors survives a restart.
Coordination
Eventual Consistency
One actor publishes its state changes; others subscribe and keep a live read-only mirror. The handshake is subscribe → snapshot → live deltas.
Lease
A subscription expires unless it is renewed — so a dead watcher is cleaned up automatically. Distributed garbage collection.
Registrar & Discovery
A directory actor. Every actor registers itself, and actors find each other by querying it rather than hard-wiring addresses.
ServiceFilter
The query used to discover services: by name, protocol, transport, owner, or tags. e.g. (name channels protocol category:0).
LifeCycleManager
Loads and unloads actors on demand (lazy), tracking each one's lifecycle state. HyperSpace is one.
Applications
Pipeline
A chain of processing elements that a stream of data flows through — Aiko's engine for ML and video. Each element transforms the frame and passes it on.
